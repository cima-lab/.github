# Contributing to CIMA Lab

CIMA Lab hosts multiple faculty-led projects under one umbrella organisation.
This document covers the defaults shared across all of them; an individual
repository may add more specific guidance on top.

## Ways to contribute

- **Code or bug fixes:** open a pull request
- **Bugs or feature ideas:** open an issue using the provided templates
- **Academic, clinical, or industry collaboration:** email cimalab@gmail.com — see
  the partnership process below

## Pull requests

- Keep changes focused; describe what changed and why
- New repositories should include a README, a `LICENSE`, a pinned
  dependency/environment file, and — for repos tied to a publication — a
  `CITATION.cff`
- Prefer config-driven experiments with fixed seeds; a paper's claims should
  map to a runnable script

## Licensing

Unless a project has a specific reason to do otherwise, new CIMA Lab
repositories use the [MIT License](LICENSE).

## Clinical and human-subject data — read before contributing

- No patient or human-subject data may be committed to any repository, public
  or private, without prior IRB approval and a signed data-use agreement
- No patient data on personal devices or public cloud storage without approval
- If you're unsure whether data is in scope, ask before pushing — see
  [SECURITY.md](SECURITY.md)

## Partnership process

Academic, clinical, and industry partners can reach out to cimalab@gmail.com.
Requests are checked against fit with the lab's four research areas, and,
where human data is involved, routed through IRB and data-use review before
any collaboration starts.
